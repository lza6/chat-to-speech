1. 上下文与直觉

为什么做这个

项目是纯前端单文件静态页（demo.html + sw.js + site.webmanifest），三闭环：AI 对话 / 文本转语音 / 整页朗读。v4.1 已上线生产（tag v4.1.1），但有两个被忽略的"塌方点"：

  1. 断网 + 无系统中文包 = 无声：v4.1 的降级链是 引擎1(在线 F5-TTS) → 引擎2(浏览器 SpeechSynthesis) → 引擎3(文本兜底)。在线端点 2026-09-06 起持续 502，而 Linux 多数发行版没有中文语音包 → 引擎2 也失败 → 直接塌到文本兜底（无声）。这是 L1 级失效，不是体验差，是工具死亡。
  2. 降级链实际没有第四选择：本地 WASM TTS 是唯一能"摆脱外部端点 + 系统音色双重依赖"的出路。Kokoro 82M ONNX 模型（Apache-2.0）+ 中文音素器是成熟方案，但 v4.1 的调研停在"候选确认"，没有落地。

直觉判断：先移植已被社区验证的中文音素器（kokoro PR #352，closed-unmerged 但 diff 可取回），再插入降级链成为引擎1.5。但"代码写上"≠"生产可用"——必须经过独立审查线程（CRITIC）从需求/逻辑/边界/质量/测试/实测六维反向攻击，把伪闭环拆掉。

4. 剩余风险与边界

  • 真机出声待测（结构性前提已标注）：语音质量官方自评 C/D（非「高质量」）；iOS Safari WASM 内存限制未验证。
  • 'unsafe-eval' 引入：WASM 引擎1.5 必需；v4.3 P3-1 计划用编译后的 wasm 收敛。
  • 预检与模型拉取间隔：canUseZhWasm 只测两个依赖 import，HF 模型 fetch（82MB）在首次合成时才发生——自检通过 ≠ 模型一定能拉下来，但失败会透出到状态栏并回落引擎2/3。
  • 内联音素器双实现漂移：demo.html 内联版与 tts-zh.js 独立维护（单文件部署约束），U_ZH_8 的 WAV 断言 + U_ZH_4/5 的 IPA 断言提供回归保护，但改动需两处同步。

📋 变更测验（你必须通过）

逐题选择，点击"显示答案"自检。答错请回读对应章节。

Q1. v4.1 的降级链是几级？v5 插入引擎1.5 后变成几级，插入位置在哪？
✅ B。v4.1 是 引擎1(在线)→2(浏览器)→3(文本兜底) 三级；v5 插入引擎1.5（本地中文 WASM）成为 引擎1→1.5→2→3 四级降级链。
Q2. kokoro-js@1.2.1 直接传 voice: 'zf_xiaobei' 给 generate() 会发生什么？v5 用什么绕开？
✅ B。kokoro-js@1.2.1 的 _validate_voice 白名单只有 28 个英文 voice，zf_xiaobei 必被拒。v5 用 generateZhWithVoice 走 tokenizer → input_ids → generate_from_ids（不校验 voice，且避免二次 espeak 音素化）。
Q3. v5 引擎1.5 的触发判定为什么从「首字符非 ASCII」改成「含 CJK 汉字」？
✅ B。`' 你好'`（前导空格）旧判定误不触发；`'ＡＢＣ'`/`'😀'` 误触发。改为 /\p{Script=Han}/u 后仅含 CJK 汉字才走引擎1.5。
Q4. 引擎1.5 为什么不能整段合成，而要分块合成？
✅ B。Kokoro STTS2 上下文窗口有限，5000 字无标点串整段塞给 phonemize 会 truncation:true 截断丢尾。v5 复用 splitIntoChunks 逐块合成拼接。
Q5. 引擎1.5 已真实闭环到哪一步？还有哪一步必须真机才能确认？
✅ B。57/57 测试全绿 + vendor 可 import + CSP 放行已真实验证；「真机出声」是 82MB 模型 + WASM 推理，headless 不可跑，代码路径已通但需你真机跑 ⚙️ 引擎1.5 自检 → 朗读中文复验。
