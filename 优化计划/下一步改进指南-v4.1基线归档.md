## 〇、第一性原理：这个工具的本质是什么？

剥到最底层，"在线聊天转语音"做的是四件事的串联：

```
[意图表达] → [语义生成/文本提取] → [文本→声波] → [人耳感知]
   输入框         聊天模型/整页提取      TTS 引擎链       播放 + 视觉反馈
   语音听写        推理清洗             在线/WASM/浏览器   频谱/高亮/续读
```

**任何一环断裂，工具就失效。** 但"失效"有程度之分：

| 失效等级 | 表现 | 用户感受 | v3 现状 |
|---------|------|---------|---------|
| L0 完全哑火 | 无声、无反馈、白屏 | 工具死亡 | v3 已消除（三级降级链） |
| L1 降级塌方 | 有声但机械/无中文/不可下载 | 能用但难用 | v3 仍存在（Linux 无 zh 包时） |
| L2 体验断裂 | 有声但无字级高亮/无续读/无可视化 | 能用但低端 | v3 普遍存在 |
| L3 被外部决定 | 端点宕机/模型漂移/库黑盒 | 可用性被别人决定 | v3 核心痛点 |
| L4 单文件天花板 | 1188 行难维护/无类型/无组件 | 演进受阻 | v3 接近极限 |

**v4+ 的核心命题**：

> **把"保活"升级为"保好"，把"被外部决定"升级为"用户自给自足"，把"单文件能用"升级为"单文件可演进"。**

同时不破坏 v3 的核心价值三角：

1. **纯前端**（无后端、无注册、无 API Key 硬编码）
2. **无构建**（`demo.html` + `site.webmanifest` + `sw.js` 三文件可直接托管）
3. **单文件可部署**（GitHub Pages/Vercel/Netlify/Nginx/CDN 任意静态托管）

**任何 v4+ 改动不得破坏此三角**。若某项升级必须引入构建（如 v6 模块化），须用 `vite-plugin-singlefile` 等方案保持"部署产物仍是单文件"。

## 二、v4 迭代路线图（韧性 + 自主 + 离线高质量）

**v4 主题词：让工具不再被别人决定，让降级不再是塌方。**

### P0-1（v4）引入引擎1.5：本地 WASM TTS，摆脱外部端点 + 系统音色双重依赖

**根因**：v3 的降级链在"在线端点宕机"且"系统无中文语音包"时直接塌方到文本兜底（无声）。这是最严重的体验断裂（L1 失效）。

**方案**：在引擎1（在线）和引擎2（浏览器 SpeechSynthesis）之间插入引擎1.5 —— 基于 WASM 的本地高质量 TTS，不依赖外部服务，不依赖系统语音包。

**候选技术（按优先级，全部待联网验证）**：

6. **WebAssembly SIMD 检测**：`WebAssembly.validate(SIMD模块)` 不支持时退非 SIMD 版本。

### P1-1（v4）Service Worker 跨域 CDN 缓存：离线时聊天功能不全挂

**根因**：v3 的 `sw.js`（第 32 行注释）明确"跨域资源不缓存"，`fetch` 事件中 `url.origin !== self.location.origin` 直接 return，导致离线刷新页面虽不白屏（demo.html 已缓存），但 `uncloseai.js` 加载失败 → 闭环①（聊天）全挂。

**方案**：对 `uncloseai.com`、`cdn.jsdelivr.net`、`cdnjs.cloudflare.com` 三个跨域源启用"stale-while-revalidate"缓存策略。
- 跨域响应是 `opaque` 类型（status 0），不能读取但**可以缓存和回放**。
- 策略：网络优先 → 失败回放缓存 → 缓存过期后台异步更新。

**落地技术点**：
1. sw.js 增加跨域资源白名单 `CROSS_ORIGIN_CACHEABLE`。
2. 跨域 fetch 用 `cache.add(req)`（不读 body，只存）。
3. 离线时 `caches.match` 回放 opaque 响应有效。
4. 缓存版本号升级触发清理（`CACHE_NAME` 版本化已就位，升级时改版本号即可）。
5. **最大缓存年龄**：跨域 opaque 响应无法读 `Cache-Control`，需设本地 TTL（如 7 天），过期后台异步更新。
6. **Workbox 评估**：若复杂度上升，可引入 `workbox-sw` 替代手写策略（但破坏"单文件无依赖"承诺，需权衡）。

**验收标准**：
- 首次在线访问后，断网刷新页面，`uncloseai.js` 从缓存加载，聊天 UI 渲染成功（T_SW_1）。
- 离线时聊天发送会失败（端点不可达），但 UI 不白屏，提示"离线模式，聊天不可用"。

**风险**：跨域缓存策略复杂，opaque 响应无法校验时效，可能缓存过期版本。需设最大缓存年龄 + 后台更新机制。

### P1-4（v4）分块策略增强：SSML 感知 + 语义边界

**根因**：v3 的 `splitIntoChunks` 按句末标点切分，但遇到 SSML 标签（v5 引入）会切断标签导致解析失败；遇到长无标点串硬切可能切断词。

**方案**：
1. **SSML 标签保护**：切分时识别 `<break>`、`<prosody>`、`<emphasis>` 等标签，不在标签内部切分。
2. **语义边界优先**：优先在句号/问号/感叹号/分号处切分；其次在逗号处；最后硬切。
3. **CJK 与英文混合**：中文按字数，英文按单词（空格），不切断英文单词。
4. **段落感知**：`\n\n` 双换行视为强分割点，优先在此切分。
5. **CHUNK_SIZE 动态调整**：根据端点最大输入长度（从端点探测响应读 `max_input_length`）动态调整，避免超长被拒。

**验收标准**：
- U_SPLIT_1/2/3/4 全过。
- SSML 标签不被切断（U_SPLIT_4，v5 SSML 落地后启用）。

**风险**：切分逻辑复杂化可能引入 bug。需充分夹具回归。

### P5-1（v5）SSML 韵律控制

**方案**：支持 SSML 子集输入：
- `<break time="1s"/>` 停顿
- `<prosody rate="slow" pitch="+2st">` 韵律
- `<emphasis level="strong">` 强调
- `<say-as interpret-as="date">` 数字/日期读法
- `<phoneme alphabet="ipa" ph="...">` 音标
- `<sub alias="...">` 别名替换

在线引擎透传 SSML；浏览器引擎做 SSML→rate/pitch 映射；WASM 引擎视支持度。
- **SSML 解析器**：手写正则解析（无依赖库），单元测试 U_SSML_1/2/3 覆盖。
- **SSML 编辑器**：输入框旁加"插入 SSML 标签"工具栏，一键插入常用标签。
- **SSML 校验**：解析失败给友好错误提示。

**验收**：输入 `<break time="2s"/>` 朗读停顿 2 秒（T_SSML_1）。

- 顶部加语言切换 🌐。
- 跟随 `navigator.language` 自动检测。
- 库语言 `UNCLOSEAI_LANGUAGE` 同步切换。
- **用户自定义文案**：设置面板允许覆盖默认文案（如把"朗读"改成"播放"）。
- **语音识别语言跟随**：SpeechRecognition 的 lang 跟随界面语言。
- **TTS 默认语音跟随**：中文界面默认中文语音，英文界面默认英文语音。
- **i18n 加载策略**：单文件内联 i18n（避免额外网络请求），或 IndexedDB 缓存。

**验收**：切英文后界面全英文（T_I18N_1）。

### P5-3（v5）IndexedDB 历史升级

**方案**：历史从 localStorage 20 条升级到 IndexedDB 无限容量：
- 字段：`id / text / voice / speed / ts / tags[] / favorite / engine / duration / ssml`。
- 支持标签分类（工作/学习/娱乐）。
- 支持收藏置顶。
- 支持按文本/语音/标签/时间范围搜索。
- 导出支持 JSON + CSV。
- **历史迁移**：首次启动把 localStorage 旧历史迁移到 IndexedDB。
- **分页加载**：虚拟滚动（只渲染可见项），10000 条不卡。
- **全文搜索**：用 IndexedDB 索引 + 自建倒排索引（无依赖库），或降级到 `text.includes(query)`。

**验收**：1000 条历史搜索 < 100ms（T_HIST_1）。

### P5-8（v5）朗读速度自适应

**方案**：根据文本类型自动调语速：

## 四、v6+ 迭代路线图（生态 + 平台化 + AI 原生）

**v6+ 主题词：从工具到平台，从平台到 AI 原生。**

### v6 候选方向

| 方向 | 描述 | 价值 | 难度 | 风险 |
|------|------|------|------|------|
| **朗读书签云端同步** | IndexedDB + 远端同步（用户自建后端）| 多设备续读 | 中 | 后端依赖 |
| **语音订阅源** | RSS/文章 URL → 自动朗读（podcast 生成）| 内容消费方式变革 | 中 | 内容合规 |
| **AI 语音克隆** | 用户上传 3 秒样本 → 克隆音色（接开源 XTTS/vc）| 个性化 | 高 | 合规/伦理 |
| **实时翻译朗读** | 输入中文 → 翻译 → 英文朗读（接翻译端点）| 跨语言无障碍 | 中 | 翻译质量 |
| **多人协作朗读** | WebSocket 多端同步播放（远程共读）| 教育/远程场景 | 高 | 实时性 |
| **朗读 API 开放** | 暴露 `window.chatTTS.speak(text, opts)` 供其他页面嵌入 | 平台化 | 低 | CSP/安全 |
| **WebGPU 加速** | WASM → WebGPU 推理（piper/sherpa 支持）| 性能 10x | 高 | 兼容性 |
| **插件系统** | 用户脚本注入（含 CSP 沙箱）| 生态 | 极高 | 安全沙箱 |
| **AI 摘要朗读** | 长文本 → LLM 摘要 → 朗读摘要 | 信息消费提效 | 中 | 付费 API |
| **多模态输入** | 图片 OCR → 文字 → 朗读；PDF 解析 → 朗读 | 无障碍场景拓宽 | 中 | 依赖大 |
| **情感朗读** | 文本情感分析 → 调整语速/音高/停顿 | 体验拟人化 | 高 | 模型依赖 |
| **朗读内容审核** | 敏感内容过滤（用户自定义关键词）| 合规 | 低 | 误判 |
| **协作标注** | 多用户为文本片段标注发音/韵律 | 众包语音数据 | 高 | 协调成本 |
| **离线模型分发** | P2P 模型共享（WebRTC）| 带宽节省 | 高 | 隐私 |

### v6 推荐优先序

1. **朗读 API 开放**（低成本，高复用，让本工具可被嵌入其他页面）
2. **语音订阅源**（差异化能力，竞品少）
3. **实时翻译朗读**（无障碍价值高）
4. **AI 摘要朗读**（信息消费提效，付费 API 需用户自带 Key）
5. **多模态输入**（OCR/PDF，无障碍场景拓宽）
6. **AI 语音克隆**（体验杀手锏，但合规复杂）

### v7+ 远期方向（前瞻规划）

- **实时语音对话**：STT + LLM + TTS 全双工对话（接 WebRTC）
- **多语言实时翻译耳**：输入对方语言 → 翻译 → 自己语言朗读（接 Whisper）
- **AI 主播**：新闻/文章 → AI 主播风格朗读（接情感 TTS）
- **朗读内容生成**：用户描述主题 → AI 生成内容 → 朗读（接 LLM）
- **语音生物识别**：声纹解锁（接 WebAuthn + 声纹）
- **3D 朗读头像**：WebGL 说话人头像同步口型（接 VRM/glTF）
- **脑机接口朗读**：BCI 信号 → 文本 → 朗读（前瞻，接 WebUSB/Web Bluetooth）
