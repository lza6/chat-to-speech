## 一、为什么"能打"（第一性原理）

把"打包桌面应用"剥到最底层，本质是解决三件事：

```
[1] 一个能把 HTML 渲染成窗口的引擎    → WebView2 (Windows) / WKWebView (macOS) / WebKitGTK (Linux)
[2] 一个能把这些引擎外的系统能力暴露给页面的桥  → Tauri IPC(tauri::command) / capabilities 权限模型
[3] 一个能生成安装包 + 分发的工具链     → tauri-cli → .msi/.exe/.dmg/.deb/.AppImage
```

本项目已经是"单文件 HTML + 内联 JS/CSS + Service Worker + 远程依赖（cdn.jsdelivr/HF，已进 CSP 白名单）"：
- **引擎**：WebView2 就是 Chromium，能跑 ES modules、WebAssembly（含 .wasm 引擎1.5）、`navigator.serviceWorker`、`speechSynthesis`（WinRT 实现，Windows 上自带 Huihui/Yaoyao 中文音色——正好补 Linux 无中文包的缺口）。
- **桥**：Tauri 的 capabilities 默认全拒绝，只放行你显式允许的 IPC——比 Electron 的 `require('fs')` 全局可用安全得多。
- **分发**：`tauri build` 产出安装包 + `tauri-plugin-updater`（签名更新、增量）。

**与当前架构的冲突点（几乎没有）**：
| 现有资产 | 打包后行为 | 是否需改动 |
|---------|-----------|-----------|
| `demo.html` 单文件 | 作为 Tauri 的 `frontendDist` 直接加载 | ✅ 不动 |
| `site.webmanifest` / PWA | 桌面应用不需要 PWA，但保留无害 | 可不处理 |
| `sw.js`（同源 NetworkFirst + 跨域 SWR）| 在 `tauri://localhost` 源下仍可用 → 断网缓存 chat UI | ✅ 不变 |
| `engines/*.mjs`（jsdelivr vendor）| **建议改为 `convertFileSrc` 本地资源**（离线安装包自带 → 彻底断网可用）| 小改 |
| `demo.html` CSP meta | Tauri 会用自己生成的 CSP 包裹实际响应；meta 内联 CSP 与 Tauri 的 `csp` 配置叠加 | 需对齐（见 §5）|
| 引擎1.5 82MB 模型 | 首次从 HF 下载 → `tauri-plugin-fs` 持久化到 app cache dir（比浏览器 localStorage 配额稳）| 小改 |

## 二、方案矩阵（多方案权衡）

### 方案 A：Tauri 2（推荐）
| 维度 | 评分 | 说明 |
|------|------|------|
| 技术可行 | 5/5 | WebView2 已装；Rust 后端起 `tauri::command` 做文件/剪贴板/托盘 |
| 开发成本 | 3/5 | 需 Rust 工具链（首次 ~2-3GB）+ tauri.conf.json + capabilities |
| 维护成本 | 4/5 | 版本升级少；Rust 侧只保留薄 IPC 层 |
| 性能 | 5/5 | 30-80MB 内存、2-10MB 包体 |
| 扩展性 | 5/5 | 系统托盘、全局快捷键、自动更新、多窗口、剪贴板监听 |
| 风险 | 低 | 主要是"要装 Rust"的第一步 |

### 方案 B：Electron
| 维度 | 评分 | 说明 |
|------|------|------|
| 技术可行 | 5/5 | Node + Chromium，最容易上手 |
| 开发成本 | 2/5 | 包体 80-150MB；对本项目是"杀鸡用牛刀" |
| 维护成本 | 3/5 | 每周发布期、安全补丁压力大 |
| 性能 | 2/5 | 内存 100-300MB |
| **结论** | — | ❌ 不推荐：本项目是静态页，Electron 的全部优势（Node 生态）都用不上 |

### 方案 C：Native（C# WPF/WinUI + WebView2）
| 维度 | 评分 | 说明 |
|------|------|------|
| 技术可行 | 4/5 | Windows 首选 C#，天然有 WebView2 |
| 开发成本 | 2/5 | 跨平台要重写；打包 MSIX 生态复杂 |
| **结论** | — | 仅当你确定**只出 Windows 且团队熟悉 C#** 才考虑 |

### 方案 D：先"壳级验证"（最小闭环，不装 Rust）
在决定 Tauri 之前，先用一个**极薄 WebView2 壳**（C# WinForms ~30 行或 PowerShell WebView2 COM）把 `demo.html` 直接托起来验证：
- 验证 WebView2 能加载单文件 + 内联 CSP + engines/ 相对路径 + 引擎1.5 WASM 出声。
- 30 分钟即可得到"能不能打包"的最硬证据，零 Rust 依赖。
- **推荐作为阶段 0**（见 §3）。

## 三、分阶段落地（每阶段有验收）

### 阶段 0：壳级验证（0.5 天，不需要 Rust）
**目标**：证明"单文件 HTML 在 WebView2 壳里完整工作（含引擎1.5 WASM 出声）"。

**实施**（PowerShell + WebView2 COM，或临时 C# 控制台）：
1. 拉 WebView2 对象 → `source = file:///.../demo.html`（或本地 http）。
2. 监听 `NavigationCompleted` + JS 报错。
3. 手动点朗读中文 → 引擎1.5 自检 → 出声？

**验收标准**：
- [ ] WebView2 加载 demo.html 无 JS SyntaxError
- [ ] CSP 内联 meta 在 WebView2 下生效（不会因 `unsafe-eval` 拦 WASM）
- [ ] engines/ 相对路径可解析
- [ ] 引擎1.5 ⚙️ 自检返回「✅ 依赖可用」且出声（真机）
- [ ] 断网刷新不白屏（sw.js 缓存生效或本地 vendor 直读）

**若阶段 0 失败** → 就地修（通常调 CSP 或把 `cdn.jsdelivr.net` 域名换成 tauri 允许列表），修好再进阶段 1。

### 阶段 1：Tauri 骨架（1-2 天）
```bash
# 前置：您需安装 Rust（Windows 推荐 rustup 或 winget install Rustlang.Rustup）
cargo install tauri-cli              # 或 npm i -D @tauri-apps/cli@2

# 在仓库内初始化（不破坏现有单文件！TAURI 只新增 src-tauri/ 目录）
npm create tauri-app@latest -- --template vanilla --manager npm
```
```text
项目根/
├── demo.html / sw.js / site.webmanifest / engines/   # 现有资产不动
├── dist/                        # 构建产物（把 demo.html 拷入）
│   └── index.html
└── src-tauri/                   # 新增（仅此目录）
    ├── tauri.conf.json          # frontendDist=../dist, bundle 配置
    ├── capabilities/default.json
    └── src/lib.rs               # 极薄：无命令，仅托盘/自动更新/深链（可选）
```

### 阶段 2：离线资产与 IPC（1 天）
- **engines/ 本地化**：`tauri-plugin-fs` + `convertFileSrc` 让 `import('./engines/kokoro-js.mjs')` 直读本地文件 → 断网可运行（web 版 CDN 不可达时已 fallback 到同源 vendor，桌面版直接把 vendor 变"唯一来源"）。
- **模型缓存**：`tauri-plugin-fs` 把 `model_q8f16.onnx`（82MB）写入 `app_cache_dir`，二次启动零下载（浏览器 localStorage 限制消失）。
- **IPC 预留**：`echo/version/open_external` 三个 `tauri::command`，为 v6 朗读 API 开放做准备。

### 阶段 3：安装包 + 自动更新（1 天）
- `tauri build` → `nothingv2.msi`（WiX）+ `nothingv2-setup.exe`（NSIS）。
- `tauri-plugin-updater`：GitHub Releases 作为更新端点，`tauri.conf.json` 配 `pubkey` + `endpoints`。
- **图标**：`tauri icon` 从现有 SVG favicon 生成全平台图标。

### 阶段 4：体验补齐（桌面特有）
- 系统托盘：暂停/继续/退出。
- 全局快捷键：`Ctrl+Shift+T` 唤起朗读（`tauri-plugin-global-shortcut`）。
- 开机自启（`tauri-plugin-autostart`）+ 单实例锁（`tauri-plugin-single-instance`）。
- 深链 `chattts://`（`tauri-plugin-deep-link`）：其他应用唤起后直接朗读剪贴板。

## 四、桌面版 CSP 对齐（必须改的点）

Tauri 会生成自己的响应 CSP（`security.csp` in tauri.conf.json）。当前 meta 内联 CSP 与之叠加时要明确：

```jsonc
{
  "security": {
    "csp": "default-src 'self' customprotocol: asset:; script-src 'self' 'unsafe-eval' 'unsafe-inline' https://cdn.jsdelivr.net https://huggingface.co; connect-src ipc: http://ipc.localhost https://cdn.jsdelivr.net https://huggingface.co; img-src 'self' asset: http://asset.localhost data:"
  }
}
```
- `'unsafe-eval'` 保留（引擎1.5 WASM 必需）。
- `ipc:` / `http://ipc.localhost` 是 Tauri IPC 白名单必需。
- 若阶段 2 落地本地 vendor，`cdn.jsdelivr.net`/`huggingface.co` 可从 script-src 移除 → CSP 更收。
- `media-src` 补 `asset:` 允许本地 wav 播放。

## 七、风险与回退

| 风险 | 等级 | 缓解 |
|------|------|------|
| WebView2 对 `speechSynthesis` 的中文音色 | 低 | Windows WebView2 = Chromium + WinRT 语音，Huihui/Yaoyao 可用；引擎1.5 WASM 是第二保险 |
| `unsafe-eval` 在 Tauri CSP 下被更严限制 | 中 | 在 tauri.conf.json `security.csp` 显式放行（§4 已给模板）|
| 82MB 模型 / 大缓存目录清理 | 低 | tauri-plugin-fs 持久化 + 提供"清缓存"按钮 |
| 签名与更新公钥 | 中 | tauri-plugin-updater 需生成 key 对；未签名安装包会触发 SmartScreen——首次分发建议自签 + 文档写明信任步骤 |
| **回退** | — | 阶段 0 若失败 → 维持纯 Web 形态（三文件部署），桌面化不阻塞主线 |

## 八、下一步建议（用户拍板）

1. **先做阶段 0**（本机可立即执行，零 Rust 依赖）：半小时拿到"WebView2 壳能跑 demo.html + 引擎1.5 出声"的最硬证据。
