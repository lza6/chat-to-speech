## 〇、第一性原理：这个产品的本质是什么？

剥到最底层，"在线聊天转语音"（ChatTTS）做的是四件事的串联：

```
[意图表达] → [语义生成 / 文本提取] → [文本→声波] → [人耳感知 + 视觉反馈]
  输入框/听写     聊天模型 / 整页提取       四级引擎链         播放 + 高亮 + 可视化
  语音听写        推理清洗 7 规则           1→1.5→2→3        进度 / 时间线 / 记忆
```

**任何一环断裂，工具就失效；但"失效"有程度之分。** v4.5 相比 v3 已把"保活"做到很高，但"保好"与"自给自足"仍有缺口：

| 失效等级 | 表现 | 用户感受 | v4.5 现状（`静态确认` + README `已验证`）|
|---------|------|---------|---------|
| **L0 完全哑火** | 无声 / 无反馈 / 白屏 | 工具死亡 | ✅ 已消除（四级降级链 + SW 离线缓存 + 文本兜底）|
| **L1 降级塌方** | 有声但机械 / 无中文 / 音色差 | 能用但难用 | ⚠️ 大幅缓解（引擎1.5 本地中文 WASM 已入代码），但**真机出声未验证**；若失败则回落引擎2/3 |
| **L2 体验断裂** | 有声但无可视跟随 / 无续读 / 无结构化 | 能用但低端 | 🟡 部分落地（P1-2 块级高亮镜像已入、P2-4 实时语速已入），但 SSML / i18n / 书签续读 / 音频可视化 / 语音试听 / 听写输入仍缺 |
| **L3 被外部决定** | 端点宕机 / 模型漂移 / 库黑盒 | 可用性被别人决定 | 🟡 已缓解（配置中心 + 多端点健康自愈池 A2），但**默认在线端点长期 502**，在线高质量仍依赖用户自备端点 |
| **L4 数据天花板** | localStorage ~5MB / 无跨设备 / 无检索 | 数据越用越憋 | ⚠️ 存在（历史 20 条 / 记忆 / 画像 / 看板全在 localStorage；无 IndexedDB、无全文检索）|
| **L5 单文件天花板** | 2657 行难维护 / 无类型 / 无组件 | 演进受阻 | ⚠️ 接近极限（单文件 + 无构建的"部署承诺"与"可维护性"张力，v6 需结构性解法）|

**v4.6 / v5+ 的核心命题（第一性原理推导）**：

> 1. **把"降级链"从"有没有声"升级为"每一声都值得听"** —— 引擎1.5 真机验证 + 自托管端点文档化（P0-1-A），让"在线高质量"从依赖他人变为用户可自给。
> 2. **把"能读"升级为"读得好体验好"** —— SSML 韵律 + 字级/块级高亮 + 音频可视化 + 语音试听 + 自适应语速（L2 收口）。
> 3. **把"本机数据"升级为"可检索、可续读、可成长的数据层"** —— IndexedDB + BM25 全文检索 + 书签续读 + 记忆语义召回（L4 突破）。
> 4. **把"工具"升级为"平台"** —— 公开朗读 API + 场景向导真正闭环（真 .pptx 导出）+ 多渠道模板（L5→平台化）。
> 5. **把"单文件"从负担变成护城河** —— 用"开发期模块化 + 产物仍是单文件"的方案，鱼与熊掌兼得（L5 结构性解法）。

**同时，任何升级不得破坏 v4.5 已固化的核心价值三角**（硬约束，来自 `chat-tts-evolve.skill.md` + README）：

1. **纯前端**：无后端、无注册、无硬编码密钥；用户配置的 Key 走 UncloseVault AES-256。
2. **无构建**：`demo.html` + `site.webmanifest` + `sw.js` 三文件可直接托管到任意静态服务（GitHub Pages / Vercel / Netlify / Nginx / CDN）。
3. **单文件可部署**：任何"模块化/组件化"升级，**部署产物必须仍是可直接托管的三文件**（必要时用 `vite-plugin-singlefile` 类方案，开发期享受模块化、产物期保持单文件）。

> **引擎1.5 伴随文件（不进三文件承诺，但必须入库）**：`tts-zh.js`（Node 可测音素器，与内联版双实现同步）、`engines/pinyin-pro.mjs`、`engines/kokoro-js.mjs`（jsdelivr vendor 兜底）。

### 2.1 四级降级链（核心资产，改引擎必读）

```
synthChain(text, voice, speed, myId):
  引擎1 在线 F5-TTS（probeTtsEndpoint 探测，up 才进）
    ├ pLimit(3) 并发池（对齐官方每 IP 每端点 3 req/s）
    ├ prefetchPromises[i] 幂等缓存（顺序播放保证）
    ├ 429 退避：lowerMax(2) 降并发 + fetchTTSChunk 指数退避
    └ 维持 3 在途：播放第 i 块时预取第 i+3 块
  → 失败降级
  引擎1.5 本地中文 WASM（Kokoro 82M q8f16 ONNX + pinyin-pro 音素器）
    ├ 触发条件：含 CJK 汉字（/\p{Script=Han}/u）∧ cfg.engines_enabled.engine15 ≠ false ∧ WebAssembly 可用
    ├ canUseZhWasm() 预检（WASM + kokoro-js/pinyin-pro 动态 import，结果缓存 + zhWasmFailReason 透出）
    ├ generateZhWithVoice 适配层：tokenizer→input_ids→generate_from_ids（绕过 kokoro-js@1.2.1 英文 voice 白名单，且避免二次 espeak）
    ├ 分块合成：按 splitIntoChunks 逐块 phonemize+generate+按序播放（规避超长截断）
    ├ wavFromSamples 显式 Float32/Int16/Array 分支
    └ 质量自评 C/D，徽章文案禁用"高质量"，用"本地可用"
  → 失败降级
  引擎2 浏览器 SpeechSynthesis（synthWithBrowser + stallGuard 轮询守护 onend 不触发）
  → 失败降级
  引擎3 文本兜底（synthFallbackText 复制到剪贴板）
```

### E0 · P0-1-A（先做，零代码，纯文档）：自托管 TTS 端点落地指南

- **根因**：P-4（在线高质量被外部端点决定）。配置中心已支持自带端点（`cfg-tts-endpoint` / `cfg-tts-endpoints`），但用户不知道去哪找 / 怎么起一个 F5-TTS 或 Kokoro 端点，于是『自给自足』能力空转。
- **方案**：新增 `优化计划/自托管端点指南.md`，覆盖三路线：（a）用户自有 GPU 起 uncloseai-speech（内置 Piper + Kokoro）；（b）用 Hugging Face Spaces / 任意 OpenAI 兼容 TTS 服务（只需 `/v1/audio/speech` 契约）；（c）局域网自建。文档末尾给『部署 → 填入 ⚙️ 设置 → 探测徽章变绿 → 语音列表刷新』的完整验收走查。

### E1 · SSML 子集（韵律控制）

- **根因**：P-8 的延伸 —— 朗读只有『语速一条旋钮』，无法表达停顿/强调/韵律，长文本听感平。
- **方案**：支持 SSML 子集输入（**白名单标签**）：`<break time>` 停顿、`<prosody rate pitch>` 韵律、`<emphasis level>` 强调、`<say-as interpret-as>` 数字/日期读法、`<sub alias>` 别名替换。在线引擎透传 SSML；浏览器引擎做 SSML→`rate`/`pitch` 映射；WASM 引擎按支持度近似（停顿用分块间隙实现）。
- **落地技术点**：
  1. **手写解析器**（无依赖）：一次性扫描 → 结构化 token 流 `[{type:'text'|'break'|'prosody'|'emphasis', ...}]`，**栈式处理嵌套**。
  2. **安全**：标签/属性白名单 + 属性值类型校验（time 必须 `\d+(\.\d+)?(ms|s)`），**防注入**（拒绝 `<script>`/事件属性/未知标签）。
  3. **输入工具栏**：输入框旁『插入 SSML 标签』下拉，一键插入常用标签。
  4. **解析失败**：友好错误提示 + 高亮出错位置，不静默吞错。
  5. **与 E2 联动**：切分时不切断标签（U_SPLIT_4）。
- **验收**：输入 `<break time="2s"/>` 朗读停顿 2 秒（`T_SSML_1`）；U_SSML 1-3 PASS。
- **风险**：SSML 子集与三引擎能力不对齐 → 需明确『哪些标签对哪些引擎生效』的兼容矩阵，避免虚假承诺。
- **依赖**：E2（分块联动）。

### E2 · 分块策略增强（SSML 感知 + 语义边界）

- **根因**：现有 `splitIntoChunks` 只按句末标点 + 超长硬切；遇 SSML 会切断标签、遇长无标点串会切断英文单词、遇双换行不优先分段。
- **方案（优先级由高到低）**：`\n\n` 双换行强分割 → 句末标点（。！？；.!?）→ 逗号 → 英文空格（**不切单词**）→ 硬切；SSML 标签区间视为**不可切原子**。
- **落地技术点**：CJK 按字符数、拉丁按词重（`\b` 边界）；`CHUNK_SIZE` 动态（可从端点探测响应 `max_input_length` 读，缺省回落常量）；短句合并到不超 `CHUNK_SIZE`。
- **验收**：U_SPLIT 1-4 PASS；长文朗读无跨句断。
- **风险**：切分逻辑复杂化易引 bug → 必须扩 `test-cases/` 加分块夹具回归。
- **依赖**：无（E1 依赖本节点）。

### E3 · 语音听写输入（SpeechRecognition）

- **根因**：P-8 延伸 —— 输入只有键盘，移动端/免手场景体验差。
- **方案**：输入框旁 🎤 按钮，`SpeechRecognition || webkitSpeechRecognition`，中文识别回填；识别中显 interim，结束后 final 追加到光标处。
- **落地技术点**：特性检测 `typeof Ctor === 'function'` 否则 `hidden=true`（**Firefox 默认 disabled，不得抛错**）；`recognition.lang` 跟随界面语言（E7）；长按 continuous 持续识别，松开 `stop()`；结果自动补句号（可关）。
- **验收**：点 🎤 说中文，输入框出现对应文字（`T_SR_1`）。
- **风险**：Safari 仅 webkit 前缀；需 HTTP(S) 提供（非 `file://`）。
- **依赖**：E7（语言联动，可后置）。

### E4 · 音频可视化（AnalyserNode 频谱）

- **根因**：L2 体验断裂 —— 朗读无视觉反馈（P1-2 块级高亮只解决文本侧，音频侧无）。
- **方案**：`AudioContext` + `AnalyserNode` 接入在线引擎的 `currentAudio`，Canvas 2D 画频谱/波形（**Canvas 优于 DOM bar**）。三模式：频谱条 / 波形 / 径向；色彩跟主题（`--accent` 渐变）。
- **落地技术点**：`createMediaElementSource()` 后**必须** `source.connect(analyser); analyser.connect(destination)`，否则无声；`fftSize=2048`、`frequencyBinCount=fftSize/2`、`getByteFrequencyData(Uint8Array)`；**首次需用户手势内 `audioCtx.resume()`**（autoplay policy）；离线浏览器引擎无法接入 → 显静态波形占位；低性能设备降帧 30fps（参考 `navigator.hardwareConcurrency`）。
- **验收**：在线朗读时频谱跳动（`T_VIZ_1`）。
- **风险**：autoplay policy 拦截；Analyser 接线错会静音（实为高频坑），必须有 T4 级回归保护。
- **依赖**：无（但仅在线引擎可见）。

### E5 · 语音试听（切换语音即听到）

- **根因**：语音下拉 42 项但用户不知道音色差别，选语音靠盲猜。
- **方案**：`voice-select` 的 `change` 时自动播放一句固定短示例（『你好，这是 {voice} 语音的试听』），可关闭。
- **落地技术点**：试听**不写入历史**（与 `saveHistory` 解耦）；用 `**当前语速**`；短文本（< 50 字）避免占端点配额；失败静默不打断。
- **验收**：切换语音后听到示例（`T_AUD_1`）。
- **风险**：频繁切换触发大量合成 → 需防抖 + 单次只保留最新试听。
- **依赖**：无。

### E6 · 语速范围扩展 + 预设 + 每语音记忆

- **根因**：滑块仅 0.5x-2x（`#speed-slider`），无预设、无记忆；P2-4 已实现『朗读中实时改 rate（浏览器引擎）』但范围/预设缺。
- **方案**：范围扩到 0.25x-4x + 预设按钮（0.75/1/1.5/2/3）+ `localStorage` 记忆每语音上次语速（`tts_speed_<voice>`）。
- **落地技术点**：在线/WASM 引擎语速于**合成时确定**，朗读中拖动需**下一段生效**（诚实文案，不假承诺）；仅浏览器引擎（引擎2）即时改 `.rate`。
- **验收**：预设值映射正确（`U_SPEED_1`）；朗读中拖滑块浏览器引擎即时变化（`T_SPEED_1`）。
- **风险**：三引擎行为差异需在 UI 明示。
- **依赖**：无。

### E7 · 多语言界面 i18n

- **根因**：P-8 —— 仅中文硬编码，无国际化基线。
- **方案**：全部硬编码文案抽到内联 `I18N = { zh:{...}, en:{...} }`（**内联，避免额外请求**）；顶栏 🌐 切换；跟随 `navigator.language`；库语言 `UNCLOSEAI_LANGUAGE` 同步；默认 TTS 语音跟随语言；听写 `recognition.lang` 跟随。
- **落地技术点**：`t(key, vars)` 插值；缺失 key 回退 zh（`U_I18N_1`）；**用户自定义文案覆盖**（设置面板把『朗读』改成『播放』）；`data-i18n` 属性批量扫描替换。
- **验收**：切英文后界面全英（`T_I18N_1`）+ U_I18N 1-2 PASS。
- **风险**：文案分散在 HTML 属性/`title`/`aria-label` 多处，需一次抽干，否则漏译。
- **依赖**：无。

### E8 · 无障碍深水区（axe-core + 键盘 + 屏幕阅读器）

- **根因**：P-8/P-12 —— 仅基础 aria，未做静态扫描与完整键盘导航。
- **方案**：集成 `@axe-core/playwright`（与 playwright ^1.49.0 peer 兼容）到新 E2E `e2e-test-a11y.cjs`，扫 WCAG 2 A/AA **0 严重违规**；补 Skip link、`:focus-visible`、`prefers-reduced-motion`、高对比（`prefers-contrast: more`）。
- **落地技术点**：`new AxeBuilder({page}).withTags(['wcag2a','wcag2aa']).analyze()` → `violations`；断言用真实扫描结果校准（不要照搬未验证模板）。
- **验收**：`T_A11Y_1`（violations==[]）/ `T_A11Y_2`（Tab 顺序覆盖）/ `T_A11Y_3`（ARIA label）。
- **风险**：新增依赖带 npm audit 面；`@axe-core/playwright` 版本与 axe-core 主次对齐**不遵 SemVer**，升级需注意。
- **依赖**：无。

### E9 · Lighthouse 性能预算

- **根因**：P-10 —— 不可度量则不可改进；当前 LCP/INP/CLS 未知。
- **方案**：新增 `lighthouserc.js`（**不用已归档的 budget.json**），`@lhci/cli` 在 CI 跑断言：LCP<2.5s、INP<200ms、CLS<0.1、A11y>0.95、Performance>0.9；JS 预算（gzip）< 50KB（当前 46774 B，余量充足）。
- **落地技术点**：`ci.collect.url` 指向本地 8765；`assert.assertions` 用 `maxNumericValue`/`minScore`；**TTS 请求失败会拉低 Performance** → 排除/ mock 端点请求；`numberOfRuns=3` 取 median。
- **验收**：`T_LH_1/2/3` 通过。
- **风险**：CI 环境抖动；需固定跑三次取中位。
- **依赖**：无（建议先跑一次得真实基线再收紧阈值）。

### E10 · CSP 收敛（去 unsafe-inline / 收敛 unsafe-eval）

- **根因**：P-11 —— `'unsafe-inline'` 因 uncloseai.js 内联配置脚本；`'unsafe-eval'` 为 WASM 引擎1.5 必需。
- **方案**：
  1. **unsafe-inline**：把内联配置脚本 + 内联 module 改为**外链 `app.js` + `'self'`**（**优于 hash**——hash 一改即失效、易碎）；保留 CSP 白名单。
  2. **unsafe-eval**：引擎1.5 逐步改用**预编译 wasm**（若 kokoro-js 支持不带 eval 的路径）→ 移除 `'unsafe-eval'`；不可行则保留并**在文档显式披露原因**（不假收敛）。
- **落地技术点**：外链化会改变『单文件』形状 → 需同步 README/部署说明（成为两文件：demo.html + app.js；仍属无构建静态托管，可接受）；**或**保持内联 + `'sha256-...'`（固定脚本变时手动重算）。
- **验收**：`T_CSP_1`（无 unsafe-inline 违规报告）。
- **风险**：外链化与『单文件』承诺有张力 → 建议先评估方案 A/B（见 v6 架构演进），不要贸然破坏单文件。
- **依赖**：v6 架构演进（互斥/耦合）。

> **E10 与 v6 架构演进的关系**：若采 v6 方案 A（JS 抽到 app.js），则 E10 的自然落地；若坚持单文件 hash，则 E10 需在每次改内联脚本时重算 hash（需脚本辅助，但『无构建』下只能手工维护）。**建议 E10 与 v6 同期评估。**

## 三、v5「智能 + 数据层 + 平台化」（V5-1 … V5-10）

**主题词：让数据能搜、能续、能成长；让工具能被嵌入、能自己知道自己健康。**

### V5-1 · IndexedDB 历史升级 + BM25 全文检索

- **根因**：P-9 —— 历史仅 20 条 localStorage，无标签/收藏/检索/分页。
- **方案**：历史迁移到 IndexedDB（无限容量）；字段 `id/text/voice/speed/ts/tags[]/favorite/engine/duration/ssml`；**纯前端 BM25 倒排索引**（零依赖，参考 45 行 BM25 实现）做全文检索。
- **落地技术点**：
  1. 首次启动把 `tts_history` 旧历史**迁移**到 IDB（幂等，失败可重试）。
  2. 虚拟滚动（只渲染可见项）， 10000 条不卡。
  3. 检索：BM25 字段加权（text 高权重）+ 倒排候选集剪枝 + 归一化三权重（`0.4*recency + 0.3*access + 0.3*type`）+ RRF 融合。
  4. `navigator.storage.persist()` 申请持久化存储（不支持则跳过，IDB 仍可用）。
  5. 导出 JSON + CSV；收藏置顶；时间范围过滤。
- **验收**：1000 条历史搜索 < 100ms（`T_HIST_1`）；U_IDB 1-3 + U_BM25 1-3 PASS。
- **风险**：存储配额（WASM 模型 82MB 与历史争额）；迁移失败丢数据 → 迁移失败**不删旧**。
- **依赖**：无（纯前端）。

### V5-2 · 书签 + 断点续读

- **根因**：L2/L4 —— 长文朗读中断后只能从头再来，无续读。
- **方案**：每块完成记录当前位置（按 **text hash** 区分多文本）；刷新/中断后提示『从上次断点继续』；书签列表显示进度百分比。
- **落地技术点**：进度写 IDB（非 localStorage，支撑长文）；块索引 + 字符偏移双存（文本微改也能近似定位）；与 `stopPlayback` 的 `isStopped` 守卫复用。
- **验收**：中断后刷新，提示续读点（`T_BM_1`）+ U_BM 1-2 PASS。
- **风险**：文本变更后断点失准 → 用 hash 校验，不匹配则提示『文本已变，从头？』。
- **依赖**：V5-1（IDB）。

### V5-3 · 多说话人混读（对话模式）

- **根因**：L2 —— 对话文本（`张三: xxx`）只能同一声读，无分角色。
- **方案**：识别 `名字：/名字:` 前缀，为每个说话人分配语音，朗读时自动切换；旁白行用默认语音。
- **落地技术点**：说话人正则需兼容中英冒号 + 可选空格；设置面板为每人分配语音；导出对话音频（多段拼接）；与现有 `splitIntoChunks` 的块队列衔接（块内带说话人标记）。
- **验收**：对话文本自动分语音朗读（`T_MULTI_1`）+ U_DIA 1-2 PASS。
- **风险**：误识别普通冒号行（如 URL）→ 需『说话人列表』确认门 + 可手动禁用。
- **依赖**：无。

### V5-4 · 朗读速度自适应

- **根因**：L2 —— 全程一个语速，数字/代码/标题听感不适。
- **方案**：按文本类型自动调语速（标题 0.9x / 正文 1.0x / 数字或代码慢速 + 逐字符 / 长段稍快 1.1x / 标点密集情感增强）；可关闭。
- **落地技术点**：分块时给每块打 `kind` 标（正则识别数字/代码/标题），播放时按块改语速（**浏览器引擎即时，在线/WASM 下一块生效**）。
- **验收**：数字段慢于正文（`T_ADAPT_1`）+ U_ADAPT 1-2 PASS。
- **风险**：过多变速反而突兀 → 仅对明显类型生效 + 可关。
- **依赖**：E2（分块带元信息）。

### V5-5 · 记忆语义召回 + 画像强化 + 技能结晶增强

- **根因**：P-9/L4 —— 记忆已三层但**只能列表展示，不能语义召回**；画像克制更新已入但无检索加权。
- **方案**：在记忆层上叠 BM25 + 时间/访问加权召回（复用 V5-1 的检索器）；画像更新保留『相似事实强化计数不覆盖 + 2000 字硬限』；结晶门控保持四维，新增 `score = confidence × relevance × recencyBoost`。
- **落地技术点**：记录公共字段（`id/type/content/priority/tier/topics/source/version/supersedes/attributed_to/confidence/reinforcement_count`）；类型 TTL 不衰减集（画像/偏好不参与衰减）；RRF 双通道（关键词 + 时间）融合。
- **验收**：`U_MEM_5/6` PASS（RRF 排序 + 不衰减集）。
- **风险**：召回不准反而烦 → 召回结果需可解释（展示命中词）+ 可删。
- **依赖**：V5-1（BM25 检索器）。

### V5-6 · 可观测性：本地统计 + 可选上报

- **根因**：L3/横切 —— 时间线已有 200 条环形日志，但无聚合统计，无错误聚合视图。
- **方案**：本地统计（朗读次数/时长/引擎分布/成功率/失败原因 TopN）+ 可选错误上报到**用户自建端点**。
- **落地技术点**：**默认关闭是硬约束**，禁止硬编码上报地址；上报内容先脱敏（复用 `pushTimeline` 的密钥脱敏）；提供『导出诊断包』（时间线 + 统计 + 环境信息，不含密钥）。
- **验收**：错误上报开关默认关闭且可控（`T_OBS_1`）。
- **风险**：隐私红线 → 上报端点必须用户填；无端点则仅本地。
- **依赖**：无。

### V5-7 · PWA 完整化 + 移动端触摸优化

- **根因**：P-12/L2 —— manifest 仅基础，无 shortcuts/screenshots/display_override；触摸手势未适配。
- **方案**：
  1. `display_override: ["window-controls-overlay", "standalone"]` + `shortcuts`（朗读剪贴板/朗读输入框）+ `screenshots` + 离线回退页。
  2. **File Handling API**（拖入 .txt 直接朗读）+ **Share Target**（从别的应用分享文本过来）+ **Protocol Handler**（`web+chattts://`）+ **Badge API**（朗读中角标）。
  3. 触摸：`touch-action: manipulation`（去 300ms 延迟）+ 历史项左滑删除（方向阈值判定，与横向滚动不冲突）+ `navigator.vibrate` 微反馈 + `env(safe-area-inset-*)` 刘海/手势条适配 + `viewport-fit=cover`。
- **验收**：PWA 安装后独立窗口（`T_PWA_1`）；移动端历史左滑删除（`T_MOBILE_1`）。
- **风险**：File Handling / Share Target / Protocol Handler **部分浏览器不支持** → 需特性检测降级，不得报错。
- **依赖**：无。

### V5-8 · 场景向导升级：真 .pptx 导出 + staged-change 审批

- **根因**：P-7 —— B4 PPT 只导 Markdown 文本（非二进制）；B5 电商无『草稿→预览→确认→应用』门。
- **方案**：
  1. **PPT**：引入 `pptxgenjs`（**已验证**可浏览器直出真实 .pptx，jsdelivr CDN 可达）→ 把 `wzParsePptSpec` + `wzDetectOverflow` 的几何审计结果（autofit 缩字/溢出标记）映射为真实幻灯片；保留几何预审（render→look→fix）。CSP 需放行 `cdn.jsdelivr.net`（已在白名单）。
  2. **电商**：升级为 `propose → preview(diff) → approve → apply` 四态（字段级 diff + guardrails 双重校验 + 来源纪律：无证据不写规格）。
  3. **任务看板 B3**：新增任务时支持 `deps`（依赖满足门） + `acceptance_criteria`（验收卡），与 A3 台账互通。
- **落地技术点**：pptxgenjs 动态 `import()`（按需加载，不阻塞首屏）；导出复用现有 `esc` 防注入；模板锁事实（每页只允许 title+bullets）。
- **验收**：`U_PPTX_1` + `T_PPTX_1`（导出的是 ZIP 签名 `PK\x03\x04` 的二进制 pptx，可被 Office 打开）。
- **风险**：pptxgenjs 体积（按需加载缓解）；CSP 需确认 jsdelivr 已放行（已在）；真实 .pptx 验证需 Office/WPS 人工确认（`待验证`）。
- **依赖**：无（但建议在 E10 CSP 收敛前完成，避免外链化后重调）。

### V5-9 · 公开朗读 API（可被其他页面嵌入）

- **根因**：L5 —— 工具无法被复用，无法成为平台。
- **方案**：暴露 `window.chatTTS = { speak(text, opts), stop(), on(event, cb), version }`；支持 `postMessage` 接收跨页调用。
- **落地技术点**：`opts = {voice, speed, engine?, ssml?}`；**来源校验**（postMessage 严格校验 origin 白名单，防 XSS/CSRF）；与现有 `speak()` / `stopPlayback()` 复用；发布事件（`start/progress/end/error`）。
- **验收**：`U_API_1`（API 形状）+ `T_API_1`（页面内可调用）。
- **风险**：开放 API 扩大攻击面 → 默认仅同源；跨源需显式白名单。
- **依赖**：无。

### V5-10 · 流式 TTS + Web Worker（首字节延迟优化）

- **根因**：L2 性能 —— 长文首字节延迟 ~2s（等首块合成）；WASM 推理在主线程可能卡 UI。
- **方案**：
  1. **流式**：在线/WASM 若支持流式音频，用 `ReadableStream` 边合边播；否则用现有并发预取（已实现 i+3）进一步提前。
  2. **Worker**：把 WASM 推理移到 Web Worker（需 SharedArrayBuffer → 需 COOP/COEP 头，**GitHub Pages 不支持，Vercel/Netlify/Cloudflare Pages 支持**）；不支持时退主线程 WASM。
- **落地技术点**：Worker 与主线程用 `postMessage` 传 PCM（Transferable ArrayBuffer 零拷贝）；首字节指标入时间线。
- **验收**：`T_STREAM_1`（首字节延迟低于非流式）。
- **风险**：COOP/COEP 静态托管限制；SharedArrayBuffer 需跨源隔离。**不可达时退主线程，不得假声称已 Worker 化**。
- **依赖**：V5-1（指标入库）。

## 四、v6「生态 + AI 原生 + 桌面深化」

**主题词：从工具到平台，从平台到 AI 原生；同时收口单文件天花板。**

### 4.1 v6 候选方向矩阵（含多维度评估）

| 方向 | 描述 | 价值 | 技术可行性 | 成本 | 维护 | 风险 | 落地形态（不破坏单文件）|
|------|------|------|-----------|------|------|------|--------------|
| **朗读 API 开放** | `window.chatTTS` + postMessage | 平台化 | 5 | 1 | 1 | 1 | 已在 v5-V5-9 完成 |
| **语音订阅源** | RSS/文章 URL → 自动朗读（播客）| 内容消费变革 | 4 | 3 | 2 | 3 | 纯前端 fetch + 队列 |
| **实时翻译朗读** | 输入中文 → 翻译端点 → 外文朗读 | 跨语言无障碍 | 4 | 3 | 2 | 3 | 用户自带翻译端点 |
| **AI 摘要朗读** | 长文 → LLM 摘要 → 朗读 | 信息提效 | 4 | 3 | 2 | 3 | 复用聊天端点 + 自带 Key |
| **多模态输入** | 图片 OCR / PDF → 文本 → 朗读 | 无障碍拓宽 | 3 | 4 | 3 | 4 | 动态 import OCR 库（按需）|

### 4.3 架构演进（不破坏单文件部署承诺）

单文件 2657 行已接近可维护极限（P-6）。三条路线：

- **方案 A（推荐渐进起点）**：保持 `demo.html` 为唯一入口，把内联 JS 抽到 `app.js`（ES module，`<script type="module" src="app.js">`）。部署变两文件（demo.html + app.js），仍是**无构建静态托管**。副作用：E10 的 CSP 收敛自然完成（去 `'unsafe-inline'`）。
- **方案 B**：Vite + 模块化开发，产物用 `vite-plugin-singlefile` **打回单 HTML**。开发体验好，部署产物仍是单文件；代价：引入构建工具链（与『无构建』承诺冲突）→ 仅作**开发期可选**，CI 产物仍生成单文件。
- **方案 C**：Web Components（`<tts-player>` / `<chat-panel>` / `<read-page>` / `<wizard-board>`），零依赖组件化，可嵌入他页。

> **推荐路径**：**A → C 渐进**；B 仅作可选开发工具。**硬约束**：任何时候 `demo.html`（或 `demo.html + app.js`）都必须能直接丢到静态服务器就跑，不得需要 `npm run build`。
