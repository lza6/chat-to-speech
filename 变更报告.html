1上下文

这是一个纯前端单文件 demo.html，接入远程 uncloseai.js 库，在同一页面内实现三条闭环：①AI 对话（文本输入 → AI 回复展示）②文本转语音（输入文本 → 选语音播放 → 可下载）③整页朗读（一键朗读页面主要内容）。

v1 已跑通三条闭环，但存在若干阻断性与体验性缺陷：最严重的是停止播放时进入死锁，导致后续操作无响应；其次是下载的音频不完整、整页朗读把按钮文字和 41 个语音名也读出来、空格快捷键在按钮上双重触发等。v2 围绕这些问题逐项修复，并对 PWA manifest、CSP 策略做了配套调整。

2直觉与权衡（跳过了什么、为什么）

  • 跳过 Service Worker 离线缓存：Blob URL 在 Chrome 受 scope 限制注册 SW 不可靠，强行接入反而引入难以调试的缓存问题。当前单文件 demo 的核心路径依赖远程库与网络 API，离线收益有限。升级路径：若未来需要离线，应先剥离远程库依赖或改用同源托管。
  • 跳过 SRI（子资源完整性 hash）：远程 uncloseai.js 内容会随版本更新变化，固化 hash 会破坏加载。库本身已通过 CSP 白名单限定来源，安全性由可信源约束兜底。
  • 跳过 extractWebpageContent：实测该库函数返回空对象 {}，不可用。改用自实现的 extractReadableText() 精确控制抓取范围。
  • 保留 speed 参数：实测端点确实支持（speed=1.5 生成的音频文件比 speed=1 小，证明参数生效并影响编码）。虽非关键路径，但成本极低、收益明确，予以保留。

3做了什么（按优先级分级）

P0 — 阻断性

优先级问题根因修复验收
P0 停止播放后页面"卡死"，后续点击无响应 stopPlayback 置 audio.src='' 触发 emptied 事件，但不触发 ended 或 error。playBlob 内 await 永远挂起，Promise 链断裂。 引入 currentPlaybackResolve 句柄，stopPlayback 显式调用该 resolve 解锁 await；播放正常结束/出错时也清空句柄。 Playwright 连续"播放→停止→再播放"3 轮无挂起，isSynthesizing 状态正确复位。

P1 — 重要体验缺陷

优先级问题根因修复验收
P1 下载的音频只有最后一块 v1 下载变量只保留最后一个 blob；TTS 是分块流式返回，前面块被丢弃。 用 audioBlobs[] 数组收集本轮所有成功播放的 blob，下载时 new Blob(audioBlobs, {type:'audio/mpeg'}) 拼接；文件名含语音名 + 时间戳。 下载文件时长与播放时长一致，可完整播放。
P1 整页朗读读出按钮文字和 41 个语音名 v1 用 main.innerText 抓取所有可见文本，包含 UI 控件与下拉选项。 自实现 extractReadableText()，仅精确提取标题 + 输入框内容 + 聊天回复，过滤掉所有按钮/选项/状态文案。 朗读内容只含语义文本，不再出现"播放""下载""已加载 N 个语音"等 UI 文字。
P1 speed 参数是否生效存疑 需确认端点是否真正消费该参数。 实测对比：speed=1.5 生成文件体积小于 speed=1，证明参数被消费。保留传参。 不同 speed 值产出可听差异的语速。
P1 空格快捷键在按钮上双重触发 v1 全局监听空格，Tab 聚焦到按钮后按空格既触发快捷键又激活按钮。 监听器加 !/button/i.test(target.tagName) 守卫，按钮聚焦时空格不触发快捷键逻辑。 聚焦按钮按空格仅激活按钮，不重复触发朗读。
P1 状态栏被"已加载 N 个语音"覆盖真实错误 v1 initVoices 无条件写入成功文案，把库加载失败提示顶掉。 加守卫：仅当 tts-status 当前文案不含"失败/不可用"时才覆盖。 库加载失败时错误文案保留可见，不被覆盖。

P2 与配套

优先级问题根因修复验收
P2 历史记录同句重复堆积 v1 同一文本+语音组合被多次插入。 按 text + voice 去重，命中则移除旧条目后将最新移至头部。 同句同语音只保留最新一条，且位于顶部。
P1 进度条在新一轮合成中可能被错误隐藏 v1 用 setTimeout(800ms) 隐藏进度条，定时器可能跨越到下一轮。 用 finishId 绑定本轮请求 ID，回调中校验 speakRequestId === finishId 才隐藏。 连续两轮合成时，第一轮进度条不影响第二轮显示。
P2 PWA manifest 内中文被 URI 编码破坏 JSON data URI 形式的 manifest 含中文字符被编码后 JSON 解析失败。 改用独立 site.webmanifest 文件，UTF-8 直读。 manifest 解析正常，应用名/图标配置生效。
P2 CSP 阻止库自带字体/样式加载 库从 uncloseai.com 拉取样式与字体，未列入白名单。 在 font-src / style-src 加入 uncloseai.com。 控制台无 CSP 违规报错，库 UI 正常渲染。
P2 体验补强 v1 仅基础闭环。 动态语音列表 41+ 个、主题三态切换、错误日志、进度条、下载、历史、示例 chips、键盘快捷键。 各功能在 Playwright 下可交互且符合预期。

4验证证据（Playwright 实测）

  • 死锁修复：连续执行"播放→停止→播放→停止→播放"，无 Promise 挂起，isSynthesizing 每轮正确归零。
  • 整页朗读过滤：触发整页朗读后抓取 TTS 输入文本，确认不含"播放/下载/已加载 N 个语音"等 UI 文案，仅含标题与聊天回复。
  • 下载完整性：长文本合成后下载，文件可从头播到尾，时长与播放一致。
  • 历史去重：同一文本+语音连续提交 3 次，历史区仅 1 条且位于顶部。
  • 进度条绑定：快速连续触发两轮合成，第二轮进度条不被第一轮定时器误隐藏。
  • 状态覆盖守卫：模拟库加载失败文案存在时，initVoices 不覆盖错误提示。
  • manifest / CSP：控制台无 CSP 违规，manifest 被浏览器正确解析。

5剩余风险

  • 聊天接口 CORS：AI 对话走远程端点，若服务端未返回正确 CORS 头，浏览器侧可能被拦。当前未在服务端侧验证，仅依赖端点现状。
  • iOS 未真机测：所有验证基于桌面 Playwright（Chromium）。iOS Safari 的音频自动播放策略、audio.src='' 行为差异未真机验证，存在回归风险。
  • 远程库版本漂移：uncloseai.js 内容可变（未加 SRI），未来若库 API 变更可能破坏调用方。

6知识点速览（10 张）

用最少的字说清这次变更的关键点。读完即掌握，不用答题。

P0 死锁根因

stopPlayback 置 audio.src='' 只触发 emptied 事件，不触发 ended 或 error。而 playBlob 的 await 监听的是 ended/error，于是永远不 resolve → 第二次朗读卡死。

P0 修复机制

引入模块级 currentPlaybackResolve 句柄：playBlob 起始处登记当前 resolve，stopPlayback 在置空 src 前显式调用它 resolve('stopped')，强制解锁挂起的 Promise，闭环"停止→再朗读"。

整页朗读过滤

弃用 main.innerText（会抓到 41 个语音名+按钮文字+计数器），改用 extractReadableText()：精确选择器（标题 + 朗读输入框 + 聊天回复），兜底用 clone 节点删除 UI 元素后取文本。

完整音频下载

v1 的 lastBlobUrl 只指向最后一块，5000 字下载只剩末段。v2 改为 audioBlobs[] 数组收集所有播放成功的块，下载时 new Blob(audioBlobs, {type:'audio/mpeg'}) 拼接，文件名带语音+时间戳。

空格键防双重触发

当用户 Tab 到按钮按空格，浏览器会触发按钮 click；全局空格暂停 handler 同时跑 → 双重触发。守卫：if (e.code==='Space' && currentAudio && !/button/i.test(e.target.tagName))。

错误文案守卫

initVoices 在 waitForApi.catch 后也会跑，可能用"已加载 41 语音"覆盖"加载失败"。守卫：if (!statusEl.textContent.includes('失败/不可用')) 才更新文案。

进度条守卫

v1 用 800ms setTimeout 隐藏进度条，不绑本轮 → 新一轮刚启动就被旧定时器误藏。v2 在 setTimeout 内比对 finishId === speakRequestId，只有仍是本轮才隐藏。

主动跳过项

Service Worker 跳过：Blob URL 注册在 Chrome scope 不可靠，留独立 sw.js 升级路径。SRI 不加：uncloseai.js 远程内容会变。弃用 extractWebpageContent()：返回空 {}。speed 参数实测保留生效。

PWA manifest 文件化

data URI 内的中文字符被浏览器 URL 编码，%22 替换 JSON 引号 → 解析失败。改用独立 site.webmanifest 文件承载纯 ASCII JSON，manifest 链接指向该文件。

历史去重策略

key = text || voice（同一文本用不同语音朗读应视为不同条目）。命中后行为：移除旧条目 → 把最新 unshift 到头部，保证"最新且不重复"，最多保留 20 条。
